### The Pattern vs Instance Framework
Fundamental distinction in crypto protocols that determines survivability:

**Pattern (Forkable, Replicable)**:
- Anyone can instantiate copy of the pattern
- Value not tied to ONE deployment
- If one instance fails, others continue
- Survives via multiplication, not protection
- Examples: Uniswap V2 (forked 200+ times), ERC-20 (instantiated millions of times), Bitcoin forks (BCH, BSV, Litecoin)

**Instance (Singular, Centralized)**:
- ONE deployment that matters
- Value tied to THAT specific entity
- If instance fails, protocol dies
- Single point of failure
- Examples: FTX (one exchange, died with collapse), Solana (one chain, apps don't port), Tornado Cash (one deployment, died with sanctions)

**Hybrid (Pattern with Dominant Instance)**:
- Technically forkable but one instance captures most value
- Main deployment matters most, but forks provide insurance
- Can survive via pattern if dominant instance fails
- Best of both: network effects + resilience
- Examples: Bitcoin (one chain dominates but pattern persists via forks), Ethereum (EVM is pattern, mainnet is dominant instance), Curve (forkable but CRV token creates instance-dependence)

The asymmetry: **patterns sacrifice instance-value concentration for immortality via replication. Instances sacrifice resilience for value capture**.

### Why Crypto Gets This Wrong
Most protocols are instances pretending to be patterns, or patterns trying to create dominant instances:

**Instances Pretending to Be Patterns**:
- Solana: Says "anyone can build on us!" (pattern language) but apps are tied to specific chain (instance reality)
- Polygon: Talks about "Ethereum scaling" but you're deploying on THEIR validators (instance)
- Avalanche subnets: "Anyone can launch subnet" but subnets depend on AVAX validators (pseudo-pattern, actual instance)

**Patterns Trying to Create Instances**:
- Uniswap V3: Used business source license to prevent forks, wanted V3 to be "THE Uniswap" (instance) not just forkable pattern
- Curve: Forkable AMM (pattern) but CRV token + veCRV governance creates instance-dependence
- Aave: Technically forkable but AAVE governance + brand make instance special despite copyable pattern

The mistake: treating pattern/instance as ideology (patterns = good, instances = bad) instead of strategy. Each has tradeoffs. Patterns win for resilience. Instances win for coordination speed and network effects.
